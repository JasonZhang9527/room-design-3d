# 户型图片 → 项目 JSON 转换规范

这份规范面向人工绘制、其他 AI 和外部转换工具。生成的文件应直接兼容本仓库，无需改二维或三维渲染逻辑。以 `plan-storage.js` 的 `validatePlan()`、`normalizeDesign()` 和 `index.html` 的 `MATS`、`LIB` 为当前实现依据。结构版本为 `schemaVersion: 1`。

## 1. 转换成果

交付 UTF-8、严格 JSON 格式的 `floorplans/<id>.json`，并在 `floorplans/list.json` 登记 `{ "id": "<id>", "name": "显示名称", "file": "<id>.json" }`。JSON 不允许注释、尾逗号、NaN、Infinity，也不应填入 JavaScript 表达式（例如 `R(...)`）。

必须提供 `schemaVersion`、`id`、`name`、`units`、`rooms`、`walls`、`windows`、`doors`、`slides`。转换成果还应提供正整数 `revision`、`furniture` 数组及 `sourceNotes` 数组；没有家具、门、窗或推拉门时对应数组填 `[]`。`dimensions`、`windowHeights`、`lintels`、`walkStart`、`walkLook` 可选。

`id` 与房间 ID 使用英文字母或数字开头，后续仅含英文字母、数字、`-`、`_`；不要使用 `constructor`、`prototype`。户型 ID 在列表中唯一，房间 ID 在当前户型内唯一。列表 ID 必须与文件 ID 相同。不要把本规范的示例 ID 当成所有户型共用的 ID。

交付时同时说明：采用的尺寸、估算内容、尺寸冲突及处理方式、计算面积与图片面积的差异。把这些内容写入 `sourceNotes`，不要只留在聊天记录里。

## 2. 图片标定与尺寸取舍

1. 先辨认外轮廓、房间分区、门窗洞口、尺寸线端点，区分墙内净尺寸、轴线尺寸和外包尺寸。图中家具和面积文字只作辅助，不能替代尺寸标注。
2. 全部平面长度使用 **mm**，`units` 固定为 `mm`。坐标 X 向右、Y 向下；推荐左上方外墙内皮为 `(0,0)`，左侧及顶部外墙可使用负坐标。房间、墙、门窗、尺寸线和家具必须共享一个坐标系。
3. 优先使用用户明确提供的修正或实测尺寸，其次使用图片标注尺寸。仅无标注处按图形比例估算。若图片缩放未保持比例，分别计算 X/Y 标定比例。对照片或有透视的图片，先校正透视，不能用一条标尺直接套全图。
4. 对某个已标定跨度：`mmPerPixel = 标注长度 / 对应像素跨度`。估算点坐标为 `(像素坐标 - 原点像素坐标) × mmPerPixel`。多个标注跨度应交叉核对。共享墙角使用同一个最终坐标，避免每个房间分别四舍五入后留下缝隙。
5. 闭合检查：上下宽度、左右高度、分段长度之和应相互匹配。若冲突，记录所有原始数值和误差，说明采用哪组约束，以及哪些估算部位吸收了误差。不能同时画一个总宽、标另一个总宽；未采用的原标注可写入 `sourceNotes`。
6. 图示墙厚没有尺寸时可以估算，但必须注明。已有两室示例采用外墙 200 mm、内墙 120 mm；这只是该图的假设，不是所有户型的固定墙厚。
7. 不要为凑齐图片上的面积而无说明地拉伸房间。应用按净多边形计算面积：`abs(Σ(xi × y(i+1) - x(i+1) × yi)) / 2 / 1000000`，单位 m²。标注面积可能采用另一种口径，差异需要记录。

## 3. 房间与墙体

### 房间 `rooms`

每项为 `{ "id": "bedroom-a", "name": "卧室A", "poly": [[x,y],...], "mat": "wood", "at": [x,y] }`。

- `poly` 沿房间内侧地面边界顺序给点，至少三个点，围成非零面积的简单多边形，不自交；闭合由程序完成，不必重复第一个点。
- 地面多边形不要覆盖墙体，也不要让两个房间地面互相重叠。L 形房间必须沿凹角描点，不能用外接矩形替代。门洞阈值地面由程序补上。
- `at` 为房间文字和三维灯具位置，应位于房间内部，不应落在墙、门洞或多边形凹口内；可省略。
- `counted` 默认计入面积。`counted:false` 当前同时启用三维飘窗台（约 450 mm 高），只适合项目的飘窗表达；不要为隐藏普通房间面积随意设置它。阳台默认计入几何面积，项目没有产权面积半计规则。

### 墙体 `walls`

每项为 `[x0,y0,x1,y1,type]`，表示实心轴对齐矩形，必须 `x1>x0` 且 `y1>y0`。厚度由矩形短边体现。

| 类型 | 应用行为 | 转换规则 |
| --- | --- | --- |
| `b` | 黑色、承重图层可强调、不可拆 | 已确认的厚外墙或承重墙 |
| `e` | 灰色、不可拆 | 建筑外围护墙，不可用它替代内部薄隔墙 |
| `n` | 灰色、可拆 | 内部房间之间的薄隔墙；依照用户提供的厚外墙/薄内墙规则识别 |
| `low` | 矮墙（最高约 1 m）、当前交互允许拆除 | 确实是矮墙时使用；不要把正常隔墙写成此类型 |

本项目的图片转换约定是：**厚外墙不可拆，内部薄隔墙可拆；内部薄隔墙必须标 `n`，不能因为它在厨房或卫生间周围就标 `e`。** 若用户额外指出内部承重墙，按用户信息标 `b`。未明确可归类的墙段在 `sourceNotes` 单独指出，不得伪装成已确认结果。

必须在门窗洞口处将墙体切成若干矩形段：门窗的 `rect` 不能仍被一整条墙覆盖。不要重复叠墙，也不要用整块墙体覆盖相邻房间。现有实现不支持有角度的墙段：遇到斜墙或弧墙需要注明精度限制，不能悄悄填不兼容的线段结构。

## 4. 门、窗、门洞上方墙体

### 平开门 `doors`

```json
{
  "name": "卧室门",
  "rect": [2000, 3000, 2800, 3120],
  "h": [2000, 3120],
  "c": [1, 0],
  "o": [0, 1],
  "len": 800
}
```

这里 `rect` 是墙体中的横向门洞，墙厚为 120 mm；铰点 `h` 在门洞左下角；关闭方向 `c` 向右，开启方向 `o` 向下，门扇长度 `len` 为 800 mm。关闭端点为 `h+c×len`，开启端点为 `h+o×len`。

- `h` 应落在洞口端部，`c` 沿门洞长边。水平门洞长度通常等于 `len`，竖向门洞高度通常等于 `len`。
- `c`、`o` 使用 `[1,0]`、`[-1,0]`、`[0,1]`、`[0,-1]` 这样的方向单位向量，常规平开门二者垂直；不要填角度或世界坐标。
- 从图片弧线与铰点识别开门方向；门扇开启后应进入对应房间，避免穿墙或与家具明显相撞。
- `entry:true` 只用于入户门，会影响颜色和入户文字。
- 程序自动生成约 2100 mm 高门洞以上的过梁。不应把同一门洞过梁再放入 `walls` 或 `lintels`。**重复生成过梁会导致删除门后上方仍残留墙体。**
- 删除门会同时删除它的自动过梁。外部转换只生成原始建筑的门，不要预先把删除动作写进户型文件。

### 推拉门 `slides`

格式为 `{ "rect": [x0,y0,x1,y1], "v": true }`。`v:true` 表示洞口沿 Y 延伸，`v:false` 表示沿 X 延伸。程序自动生成上方过梁：竖向门洞约 2400 mm，横向约 2100 mm。不要重复建过梁。推拉门删除记录与平开门一样由装修方案管理。

### 窗 `windows`、`windowHeights`

`windows` 每项为门窗洞口矩形 `[x0,y0,x1,y1]`。`windowHeights` 按同一下标提供 `[窗台高度,窗顶高度]`，例如 `[900,2400]`，单位仍为 mm；省略时默认这组值。窗顶必须高于窗台。

程序在窗洞下方补窗台墙、上方补墙，并创建玻璃和窗框，因此不要在洞口再叠墙。阳台侧窗、飘窗等按实际情况单独设置窗台高度。当前装修交互不支持删除窗。

### 额外过梁 `lintels`

格式为 `{ "rect": [x0,y0,x1,y1], "height": 2400 }`，只用于未由门窗自动生成的特殊过梁（如原户型中的飘窗洞口）。当前额外过梁没有独立删除入口，因此不能借此表达可删除门的上方墙体。

## 5. 地材、家具与漫游

`mat` 必须使用以下现有材料 ID：

| ID | 材料 |
| --- | --- |
| `wood` | 橡木地板 |
| `walnut` | 胡桃木地板 |
| `tile800` | 800 地砖 |
| `tile600` | 600 地砖 |
| `marble` | 大理石 |
| `antislip` | 300 防滑砖 |
| `terrazzo` | 水磨石 |
| `carpet` | 地毯 |

默认家具格式：`{ "id":"bed-1", "type":"bed", "name":"双人床", "cx":1000, "cy":2000, "w":1500, "d":2000, "rot":0, "color":"#c9d6df" }`。

- `cx/cy` 为中心，`w/d` 为旋转前宽深，单位 mm。`rot` 为角度，平面中顺时针为正；推荐 0、90、180、270。床 `rot:0` 的床头朝上，90 朝右，180 朝下，270 朝左。
- 颜色必须为 `#RGB` 或 `#RRGGBB`，不能使用中文颜色名。每件默认家具使用独立稳定 ID；应用实例会生成自己的家具 ID。
- 类型必须来自当前 `index.html` 的 `LIB`；常用类型有 `bed`、`table`、`chair`、`sofa`、`wardrobe`、`desk`、`toilet`、`vanity`、`shower`、`counter`、`stove`、`ksink`、`fridge`、`washer`、`plant`。不要随意发明类型。若仅生成建筑，可用 `furniture: []`。
- 有意复现图中家具时应保留合理尺寸、朝向和通道，不要按文字或图标像素大小机械缩放家具。
- `walkStart`、`walkLook` 为 `[x,y]`。起点位于可通行地面，避开墙和家具，目标与起点不同。可不填，应用会采用房间位置作为备用起点。层高当前统一 2.8 m；JSON 暂不支持逐房间层高。

## 6. 尺寸线 `dimensions`

每条为 `[horizontal, at, start, segments]`，例如 `[true,-700,0,[3000,120,2500]]`。

- `horizontal:true` 时在 `y=at` 画水平线，从 `x=start` 起按 `segments` 累加。
- `horizontal:false` 时在 `x=at` 画竖线，从 `y=start` 起按 `segments` 累加。
- `segments` 均为正的 mm 长度，应等于生成几何相应跨度；墙厚若包含在该尺寸链中，作为独立分段表示。
- 标注线放在户型外侧，错开文字，避免横跨房间或门窗。画布会根据建筑和尺寸链自动扩展。

## 7. 版本与装修方案

户型结构 JSON 与导出的装修方案 JSON 是两种文件：新户型文件放 `floorplans/` 并登记；装修方案则通过“文件 → 导入方案”恢复，v2 格式包含 `format`、`version`、`floorplan`、`design`。

墙体、平开门、推拉门在装修方案中按数组下标引用：`w0`、`d0`、`s0`。已使用的户型不要调换这些数组顺序，否则会使保存的拆除记录指向其他对象。

- 仅修正墙体类型、`sourceNotes` 并增加 `revision`，其余字段与坐标不变时，当前加载器可更新已有方案的墙体分类。
- 更改坐标、门窗布局、房间结构或默认家具时，建议使用新户型 ID。旧方案保留原几何快照，同 ID 改结构不会强制覆盖已有本地方案。
- `removedOpenings`、`demolished`、`measures` 属于装修方案状态，不属于原始户型结构；不要用它们代替建筑数据。

## 8. 交付验证

1. 检查严格 JSON、ID 唯一性、单位、所有必需数组、房间材质及家具类型。图形层面还要检查多边形不自交、房间不重叠、墙与门窗不重叠；当前加载器不会自动替你完成所有几何检查。
2. 登记列表后运行 `node scripts/verify.cjs`，它会加载列表中的每个户型并执行当前数据校验。此检查不能替代与原图对照。
3. 在项目根目录运行 `python -m http.server 8000`，用 HTTP 预览，不能双击 HTML。查看二维轮廓、尺寸、地材、家具和门的开向。
4. 对照原图检查三维墙体、门窗、窗台、过梁、阳台和标签；确认门洞没有被墙封住。检查漫游起点可通行。
5. 点拆薄隔墙及门，确认二维不留拆墙虚线、三维门及其自动过梁消失；厚外墙禁止拆除。然后撤销或恢复测试修改。
6. 切换其他户型再切回，保存/另存方案，刷新并检查恢复；导出/导入包含完整户型的方案。记录未完成的验证，不要宣称仅语法通过就已经完成图片还原。

## 9. 可复制给其他 AI 的任务描述

```text
请根据附件户型图片及提供尺寸，为 room-design-3d 生成可直接加载的 UTF-8 JSON。
先阅读仓库 docs/FLOORPLAN_CONVERSION.md、plan-storage.js 的数据校验函数，
以及 floorplans/studio.json、floorplans/two-bedroom-balcony.json 示例。
按原图提取 rooms/walls/windows/doors/slides/dimensions，按需生成默认 furniture。
坐标 X 向右、Y 向下，长度单位 mm，schemaVersion=1，units=mm。
厚外墙不可拆，内部薄隔墙标 n 可拆；不要把内部薄隔墙标 e。
门窗位置必须留墙洞，门上过梁由程序自动生成，不要重复写入 walls/lintels。
优先使用实测及明确尺寸，局部缺失可估算，但须记录 sourceNotes。
尺寸冲突须记录原值、误差和取舍，面积按净多边形计算，不强行凑面积文字。
交付 floorplans/<唯一id>.json，登记 floorplans/list.json，并运行验证与二维/三维预览。
如修改已有户型，不要改变数组顺序；几何结构改变优先使用新 ID。
不要自行提交、推送或发布；交付时列出估算项和验证结果。
```

没有仓库访问能力的工具，应由使用者同时提供这份文档、一个完整示例文件及当前材料/家具类型列表。可从 `floorplans/studio.json` 起步；仅提供图片和字段名不足以保证与项目兼容。
